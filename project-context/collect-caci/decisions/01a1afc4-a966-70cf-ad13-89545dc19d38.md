Decision, as the code shows it:
- The React admin panel (`admin/`) is never deployed. It runs on a developer's machine and reaches an API through a local `/api` proxy, so CORS never applies (verified: admin/vite.config.ts comment and proxy).
- On the server, `/admin` is mounted only when `APP_ENV=development` or `ADMIN_ENABLED` is truthy (verified: config.adminEnabled in backend/src/config.js, backend/src/index.js).
- `requireAdmin` re-reads `users.is_admin` on every request, so revoking access takes effect immediately (verified: backend/src/auth.js).

Consequence to watch: the proxy target defaults to the **public beta** (`API_TARGET || 'https://caci.mrh.lol'`), so local admin edits change live beta data unless `API_TARGET` / `ADMIN_API_TARGET` points at the local API (verified: vite.config.ts; the Docker variant per CLAUDE.md).

Why (inferred): this keeps the public beta free of an admin attack surface unless someone deliberately turns it on.
