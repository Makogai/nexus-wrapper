`migrate()` (backend/src/db.js) tracks applied migrations by **filename** in `schema_migrations` and runs each file in its own transaction at API start. After that it upserts the opštine list from `src/data/opstine.js` on every boot (verified: db.js).

There is a precedent: `012_maze_scores.sql` was renamed when "Bežanija" became "Ćacilend". The `schema_migrations` row was renamed by hand locally (per docs/CHANGELOG.md 2026-11-05). Any database that still had the old name simply re-runs the file. That is harmless only because the file uses `CREATE TABLE/INDEX IF NOT EXISTS` (verified: 012_maze_scores.sql).

Rule of thumb: never edit or rename an applied migration; add a new numbered file instead (CLAUDE.md). If a rename is unavoidable, make sure the SQL is idempotent first.
