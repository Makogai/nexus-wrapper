Changing a rule number touches more than the backend constant:
- **Backend source of truth**: `POINTS_PER_CACI` / `FAKE_PENALTY` (services/scoring.js), the `is_fake` formula (a generated column in migrations/001_init.sql; changing it needs a new migration), `EARN` (services/economy.js), `LEVELS` / `SUPER_RIDE_LEVEL` (services/levels.js), cooldown / per-day / report thresholds (config.js) (verified).
- **`/meta/config`** (routes/stats.js) builds most of its `rules` text from those constants, but the fake rule's "5 minusa" is a literal (verified).
- **App FAQ** (`app/lib/screens/faq_screen.dart`) reads cooldown and per-day from config but hard-codes "10 poena", "minus 50", "5 minusa", "5 prijava", "25 poena" per ride indeks, "do 20 dnevno" and "svakih 10" for the maze (verified, around lines 96-213).
- **Game clients** hard-code their own point values (`indeksPoints = 25` in ride/ride_ui.dart, `_indeksPoints = 10` in maze/cacilend_screen.dart) (verified).

When a rule changes, grep the app for the old number, and update CLAUDE.md's "Domain rules" and the README's "Pravila igre".
