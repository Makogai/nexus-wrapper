On every API start, `migrate()` (backend/src/db.js) walks `ZEMLJE` in `backend/src/data/opstine.js`. It inserts every name it doesn't find in the `opstine` table and corrects `okrug` / `zemlja` (verified).

Consequences:
- Renaming an opština in the admin panel leaves the renamed row and **re-creates the old name** as a new row on the next boot.
- Deleting one brings it back on the next boot.

The admin `opstine` resource allows create, update and delete (verified: routes/admin.js), so this mistake is easy to make.

To change opštine:
1. Edit `src/data/opstine.js`.
2. Re-run `tools/build_map.py`, which fails if a map region has no matching opština (per CLAUDE.md).
3. Fix or merge existing rows with a migration. Matching is by `name`; there is no stable key.
