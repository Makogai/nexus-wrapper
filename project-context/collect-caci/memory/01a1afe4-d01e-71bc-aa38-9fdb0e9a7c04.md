# Collect Your Ćaci: architecture (v2, after the deeper pass)

## Components
- **API** (`backend/`). Node 22, Express 5, ESM, raw SQL through `pg`, zod *(verified: backend/package.json)*. `src/index.js` mounts the auth, oauth, cacis, admin (only when enabled), stats, social, games and store routers, with one error handler that turns `HttpError` into `{error, ...extra}` *(verified: index.js)*. The image is `node:22-bookworm-slim`, its healthcheck uses Node's `fetch`, and data lives in `/data/uploads` and `/data/models` *(verified: backend/Dockerfile)*.
- **Database**. Postgres 17 with `pg_trgm`. Migrations are applied by filename at boot, one transaction each, then the opštine list is synced *(verified: db.js)*.
- **App** (`app/`). Flutter, `provider`. `Session` holds the token, meta and change notifiers *(verified: session.dart)*. `Shell` is an `IndexedStack` of 4 tabs (Početna, Studenti, Rang, Profil) with a centre add button *(verified: screens/shell.dart)*. The games (`maze/`, `ride/`) drive a `Ticker` → `ValueNotifier` *(verified: cacilend_screen.dart)*.
- **Web image**. Flutter 3.44 build, then a `?v=<md5>` rewrite that fails the build if it doesn't match (`grep -q`), served by nginx with `/api` → `api:3000` (lazy DNS, 120 s, 12 MB) and `Cache-Control: no-cache` *(verified: app/docker/Dockerfile, nginx.conf)*.
- **Admin**. A React 19 + Vite panel, local only, plus the generic `RESOURCES` CRUD in `routes/admin.js`. Sort and filter columns come from whitelists, and constraint errors become friendly 409s *(verified: admin.js)*.

## Data flow
1. Requests carry a Bearer JWT (30 days) checked by `requireAuth` *(verified: auth.js)*. The public endpoints are `/health`, `/auth/*`, `/meta/*` *(verified: index.js, stats.js)*.
2. **Adding a ćaci** takes two uploads of the same image. First `POST /cacis/check`, where the app shows "is it one of these?". Then `POST /cacis`, which retries with `confirmedNew` on a 409 `needsConfirmation` *(verified: add_caci_screen.dart)*. On the server: cooldown → daily limit → dHash + CLIP → match → store webp (768² cover) → one transaction (claim cooldown, insert, `book` +5) → `queueHeadCut` *(verified: routes/cacis.js, images.js)*.
3. **Head cutout** runs in an in-process promise chain, one job at a time: OWL-ViT detector → background removal → transparent webp + `head_circle`. Jobs lost on a restart are re-queued by the `NOT head_done` backfill *(verified: services/headcut.js)*.
4. **Votes, comments, likes and reports** each run in a transaction and update denormalized counters by deltas. Admin writes call `recount()` to rebuild them from the source tables *(verified: cacis.js, admin.js)*.
5. **Sign-up**: hashed 6-digit code (15 min, 5 attempts, 60 s between resends, 5 mails an hour). Unverified accounts older than a day give up their username and email *(verified: services/verification.js, routes/auth.js)*.

## Boundaries and integrations
- **OAuth** (Google, Facebook, Apple): server-side code flow. `state` is a 10-minute JWT signed with `JWT_SECRET`, redirects are checked against `APP_REDIRECTS`, and accounts are linked by email. The token goes back in the redirect query *(verified: routes/oauth.js)*. The web popup posts only to its own origin *(verified: app/web/auth.html)*.
- **Local ML**: CLIP q8, OWL-ViT fp16, ormbg, downloaded into the `models` volume *(verified: similarity.js, headcut.js)*.
- **OpenAI** (optional moderation, plus the closed photo mode) and **SMTP** *(verified: images.js, verification.js)*.
- **Coolify** behind Traefik (`trust proxy` 1), with **Cloudflare** in front of the web app *(verified: index.js; per CHANGELOG)*.

## Key decisions
- Raw SQL, a shared `caciSelect()` row shape, and money only through the keyed `book()` ledger *(verified)*.
- Real photos are never stored, there is no face recognition, and a duplicate is refused only when all signals agree *(verified: cacis.js)*.
- Game scores are client-reported, bounded by zod maxima and daily caps *(verified: games.js)*.
- The admin API is opt-in, and `requireAdmin` re-checks `is_admin` on every request *(verified: config.js, auth.js)*.

## Risks and open questions
- **Critical: `POST /auth/verify` hands out a token for any already-verified account without checking the code** (`if (!user.email_verified) await checkCode(...)`, then `signToken`). Migration 013 defaults `email_verified` to true, so this covers every existing user, admins included. It came in with `cdb36c5` (2026-11-05) *(verified: routes/auth.js:92-99, 013_email_verification.sql; not tested against any server)*.
- There is no rate limiting anywhere, including login and verify *(verified: grep)*.
- Facebook emails are linked to existing accounts without a "verified" check *(verified: oauth.js)*. The OAuth `state` isn't tied to the browser that started the login *(inferred: no cookie)*.
- Image files are never deleted when a ćaci is deleted or its picture replaced by an admin. A failed create also leaves its stored image behind *(verified: cacis.js, admin.js; `removeUpload` is used for avatars only)*.
- Code attempts are checked and incremented in two separate queries *(verified; low impact)*.
- No tests or CI. The admin panel targets the beta by default. JWTs can't be revoked *(verified)*.
- Not reviewed: duplicates/moderation internals, the social and store routes, most app screens.
