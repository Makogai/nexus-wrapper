## Problem
`AppServiceProvider` (lines 46-58) binds `PaymentGatewayInterface` from `platform_config('billing.gateway')`. If that setting is `paddle` or `stripe` but the matching key is missing (`drivebay.billing.paddle_api_key` / `stripe_secret`), it returns `FakePaymentGateway` without any error or log. In production, promotions would then complete without anyone being charged. No test covers this selection logic (checked the tests with grep).

## Decision (from the learning pass)
- Outside `local`/`testing`, a configured real gateway with missing keys must fail loudly: throw at resolve time, or refuse checkout and report to Sentry.
- `fake` should only be allowed when explicitly configured and the environment is not production.

## Checklist
- [x] Change the binding in `app/Providers/AppServiceProvider.php`.
- [x] Add Pest tests: each gateway resolves with its keys; a missing key outside local throws or logs; fake is refused in production.
