## Finding
- `composer run dev` starts `php artisan inertia:start-ssr`, and `vite.config.js` has an SSR entry (`resources/js/ssr.js`).
- The production Dockerfile only runs `npm run build` (no `build:ssr`) and copies only `public/build`. The web container runs php-fpm and nginx with no Node process. Production is therefore client-rendered.
- SEO meta (title, description, canonical, robots, OG and Twitter tags) is rendered server-side by Blade from `page.props.seo` in `resources/views/app.blade.php`. Share previews and crawlers get the meta without SSR.

## Decision (from the learning pass)
- Keep production client-rendered.
- Remove `inertia:start-ssr` from the `dev` script (and drop the SSR entry if nothing else uses it), so dev behaves like production. SSR-only bugs and SSR-only rendering stop showing up in dev alone.
- Revisit only if the SEO epic (KAN-62) needs server-rendered body content.
