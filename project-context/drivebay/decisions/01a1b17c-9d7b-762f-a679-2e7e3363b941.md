**Decision (visible in code, KAN-7):** `ImportAutodilerListingsJob` (`$timeout = 900`) runs on:

- its own connection, `redis-imports` (`retry_after` 1200 s, env `REDIS_IMPORTS_QUEUE_RETRY_AFTER`, in `config/queue.php`);
- its own queue, `autodiler-imports`;
- its own supervisor, `supervisor-imports` (timeout 960 s, `maxProcesses` 2 in production and 1 on dev, in `config/horizon.php`).

The default `redis` connection keeps `retry_after` 90 s, and `supervisor-1` keeps a 60 s timeout.

**Why:** a 900 s job on the default connection would be picked up again before it finished. Laravel requires job timeout < supervisor timeout < `retry_after`.

**How to apply:**
- Any new job longer than about 60 s needs the same treatment.
- A new supervisor must also be listed under every environment in `config/horizon.php`. Defaults alone do not start it, as the comment there says.
- On Windows, Horizon needs pcntl, so `composer run dev` uses `queue:listen` instead.

(verified: config/queue.php, config/horizon.php, app/Jobs/ImportAutodilerListingsJob.php)
