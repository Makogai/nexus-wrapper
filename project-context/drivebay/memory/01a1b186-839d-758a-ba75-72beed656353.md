# DriveBay — architecture summary (draft v2, deeper pass)

Markers: *(verified: file)* = seen in the code; *(inferred)* = my conclusion; *(MAIW)* = from `D:\code\maiw\memory\drivebay`, not re-checked. This version replaces v1.

## Components

- **One Laravel 12 app with domain modules.**
  - 21 domains under `app/Domains/{Domain}/` hold services, jobs, console commands, DTOs, events and policies.
  - Models sit in a parallel tree, `app/Models/Domains/{Domain}/Models/` *(verified: ls)*.
  - Controllers live in `app/Http/Controllers/{Web,Api/V1,Admin}`; there are 39 API controllers *(verified: ls)*.
- **Routing** *(verified: bootstrap/app.php, routes/)*:
  - `web.php`: the marketplace closure is mounted twice, at `/` (English) and under `/sr` with route names prefixed `sr.`.
  - `storefront.php`: dealer storefront hosts.
  - `api.php` → 11 files in `api/v1/` (auth, catalog, analytics, campaigns, engagement, seller, dealer, viewing, fuel-prices, tools, moderation).
- **Middleware:**
  - On every web request, `ResolveDealerStorefrontHost` runs first. It sets a request-wide `StorefrontContext` to marketplace or standalone, or returns 404 for an unknown or unverified host *(verified: middleware, AppServiceProvider singleton)*.
  - Then `SetLocale`, `EnsureEngagementVisitor` and `HandleInertiaRequests` run.
  - The API adds `SetApiLocale`. Rate limiters: `api-auth` 10/min per IP, `api-search` 60/min, `api-analytics` 120/min, `api-write` 30/min, `api-import-status` 180/min, plus a limiter for the AI fuel estimate *(verified: AppServiceProvider)*.
- **Admin:**
  - Filament 5 panel `admin` at `/admin`: SPA mode, with resources, pages and widgets discovered automatically. There are 32 resources.
  - `User::canAccessPanel` lets in only staff, as decided by `StaffAccessService` *(verified: AdminPanelProvider, User.php)*.
- **Frontend:**
  - Inertia + Vue: 41 pages under `resources/js/Pages`, four layouts (App, Guest, Error, DealerStorefront), about 100 components and 24 composables *(verified: ls)*.
  - No vue-i18n: translation tables arrive as shared Inertia props (passed through `brandify()`) and are read with `useTranslations()` *(verified: HandleInertiaRequests; composable name from Graphify)*.
  - Calls go through Inertia; only 2 files use axios *(verified: grep)*.
- **Cross-cutting helpers:** `brand()` / `brandify()` (packs in `config/brands/`) and `platform_config()`. Boolean keys resolve through Pennant flags in global scope; other keys use a stored admin override, falling back to config *(verified)*.

## Data flow

1. **Creating a listing (web)** *(verified: SellerListingController, ListingMediaService, ProcessListingMediaJob, ListingPublishCoordinator)*:
   - `ListingService::createDraft(CreateListingDTO)` → link the listing to the dealer → sync equipment.
   - **With photos:** the status becomes `processing` and each photo is queued as a `ProcessListingMediaJob` (watermark + variants via Intervention Image). When no asset of the listing is still `queued` or `processing`, `ListingPublishCoordinator` publishes it with auto-approve.
   - **Without photos:** it is published immediately with auto-approve.
2. **Publishing** *(verified: ListingService::publish)*:
   - Auto-approve → `status=active`, `moderation_status=approved`, then the `ListingPublished` event and `SyncListingSearchDocumentJob`.
   - Otherwise → `pending_review` and a notification to staff.
   - The manual "publish" action in the web and API seller controllers auto-approves only when `user.type === 'private'`.
   - Statuses are plain strings, not enums: `draft`, `processing`, `pending_review`, `active`, `rejected`, `sold`, `archived`.
3. **Imports (Autodiler):** `ListingModerationPipelineService` runs `ListingAutoPublishEvaluator`. It may auto-approve photos (`moderation.require_admin_photo_approval`) and publishes only when the evaluator allows *(verified)*.
4. **Events:** there is only one domain event, `ListingPublished`, which drives `SendListingPublishedNotification` and `NotifySavedSearchMatches`. Other side effects are direct service calls, jobs, or the observers `NotificationObserver` (sends a push for in-app rows, per MAIW) and `AdvertisementObserver` *(verified: AppServiceProvider)*.
5. **Search** *(verified: config/scout.php, ListingSearchDocumentBuilder)*:
   - `ListingSearchDocument` rows are indexed in Meilisearch.
   - Filterable and sortable attributes are declared in `config/scout.php` and take effect only after `scout:sync-index-settings` (`composer run search:setup`).
   - Sort scores: freshness, popularity (views), quality, recommendation and boost.
6. **Scheduler:** recommendations rebuild nightly (03:00–04:00); alerts, appointments and promotion expiry run hourly; then purge, fuel prices, mobile.de taxonomy and the Instagram token check *(verified: routes/console.php)*.
7. **Payments:**
   - `PaymentGatewayInterface` resolves from `platform_config('billing.gateway')`. It returns Paddle or Stripe only when that provider's keys are configured; **otherwise it quietly returns `FakePaymentGateway`** *(verified: AppServiceProvider)*.
   - Stripe and Paddle webhooks are exempt from CSRF *(verified)*.
8. **Errors:** web 403/404/500/503 render the Inertia `Error` page and 419 redirects back. API responses pass through as JSON `{data, meta}` *(verified: bootstrap/app.php, docs/api/conventions.md)*.

## Boundaries and integrations

- **API contract:**
  - Sanctum bearer tokens, the `Accept-Language`, `X-Visitor-Id` and `X-Analytics-Source` headers, and the `{data, meta}` envelope *(verified: docs/api/conventions.md)*.
  - OpenAPI is exported by Scramble to `docs/api/v1/openapi.json`, which has 109 paths and 122 operations *(verified)*.
  - Web and API are meant to be separate contracts, but **9 API controllers import `Requests\Web\*`**: Account, Auth, AutodilerImport, BuyerViewing, ListingReport, Message, SellerListing, SellerViewing and Tools/FuelConsumptionCalculator *(verified: grep; MAIW said 8)*.
- **Datastores:** PostgreSQL 16, Redis 7 and Meilisearch 1.12 *(verified: compose files)*. 149 migrations; 129 tables in the DBML *(verified)*.
- **External services:**
  - Payments: Stripe and Paddle *(verified: Billing gateways)*.
  - Firebase FCM *(verified: config env names)*.
  - Sentry and Telescope *(verified: config env names)*.
  - Socialite logins: Google, Facebook, Apple *(verified: config env names)*.
  - OpenAI, for fuel-consumption estimates *(verified: FuelEconomy services)*.
  - Meta Graph, for Instagram publishing, with fake publishers for dev *(verified: Publishers)*.
  - Vehicle data: mobile.de, plus CarQuery and NHTSA (legacy) *(verified: config env names)*.
  - Autodiler scraping *(verified: config env names; scraping per MAIW)*.
  - A Montenegro fuel-price feed *(verified: FuelPricing)*.
- **Deployment:**
  - One multi-target Docker image: web (php-fpm + nginx under supervisord), worker (`horizon`) and a scheduler loop.
  - On Coolify, the app runs with Horizon, Postgres, Redis and Meilisearch; the scheduler is a Coolify cron entry.
  - Horizon has two supervisors (`default`, and `autodiler-imports` on the `redis-imports` connection).

## Key decisions

- **A modular monolith by domain,** designed so it can move to services later *(verified: docs/architecture/system-overview.md)*.
- **Brands are packs chosen at deploy time** (`BRAND`), not an admin CMS *(MAIW; packs verified)*.
- **Locale lives in the URL** for the web (English unprefixed, `/sr`) and in a header for the API *(verified)*.
- **Long imports get their own queue, connection and supervisor** (KAN-7): timeouts ordered 900 s < 960 s < 1200 s *(verified)*.
- **Publish first, moderate after** for most listings (a new listing auto-approves). Staff review mainly comes from reports, warnings, quick edits and unpublishing (`ListingModerationService`) *(verified methods; overall policy inferred)*.
- **Image processing is custom.** Spatie Media Library was removed (KAN-16) *(verified: composer.json; MAIW)*.
- **Paddle is a third gateway,** not Cashier *(MAIW; gateway verified)*.
- **Spatie roles are the source of truth for staff** (KAN-58) *(MAIW; admin access verified)*.

## Risks and open questions

- **Silent fake payments:** if production has the gateway set to `paddle` or `stripe` but a key is missing, checkouts go through `FakePaymentGateway` without any error *(verified code path; impact inferred)*.
- **Dealers' manual publish goes to `pending_review`** while private sellers auto-approve, yet the create-with-photos path auto-approves everyone. Is that intended? *(verified code; intent unknown)*
- **The schema doc (DBML) has drifted.** The repo calls it "the only truth for schema", but:
  - it lacks app tables that migrations create: `advertisements`, `database_notifications`, `email_verification_codes`, `engagement_campaign_target_{locales,routes}`, `fuel_consumption_estimates`, `recommendation_profile_*` (5 tables), `user_device_tokens`;
  - it models roles as `roles/role_user/permission_role`, while Spatie uses `model_has_roles` and `role_has_permissions`;
  - the `media` table (from the removed Media Library) is still created *(verified: comm of migrations vs DBML)*.
- **The OpenAPI file is stale.** It was last exported 2026-08-03, but `POST /billing/paddle/complete` (2026-08-04) is missing from it *(verified: git log, grep)*.
- **SSR in production?** It runs in dev (`inertia:start-ssr`), but the web container runs no Node process *(inferred gap)*.
- **Test database differs from production.** Tests use SQLite in memory with a sync queue, while production uses Postgres and Redis *(verified: phpunit.xml)*.
- **The Pennant setup is inconsistent:** `AppServiceProvider` defines 13 features, while `app/Features` has 15. The two moderation flags are not defined there but are read through `platform_config` *(verified)*.
- **Out-of-date docs:** the repo's CLAUDE.md and the MAIW `INDEX.md` summaries. See the memory note on drift.
