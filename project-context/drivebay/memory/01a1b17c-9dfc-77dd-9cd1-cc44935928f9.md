Before adding a new switch or setting, check these three mechanisms (all autoloaded through `composer.json` `files`):

1. **Brand:** `brand($key)` reads `config/brand`, chosen at deploy time from the packs `config/brands/drivebay.php` and `autoklik.php`. `brandify()` replaces `:app` in strings, and every Inertia translation table passes through it in `HandleInertiaRequests`. So user-facing copy should say `:app`, not a hard-coded "DriveBay". (MAIW decision of 2026-07-28; Flutter mirrors it with `--dart-define=BRAND`.)
2. **`platform_config($key)`** (`app/Support/Settings/PlatformConfigService.php`): keys are declared in `config/platform_config.php`, and each key's definition has a `config` path and a `type`.
   - Boolean keys with a `pennant` entry resolve through `Feature::for(null)->active(...)`, a Pennant flag in global scope.
   - Other keys use a stored, admin-editable override, falling back to config. Overrides are cached; the service clears the cache when they are saved.
   - An unknown key throws `InvalidArgumentException`.
3. **Pennant:** 15 feature classes in `app/Features/`, such as `InstagramPublish`, `ModerationAutoPublishImports`, `StorefrontSubdomain` and `PriceRating`. The repo's CLAUDE.md wrongly says 14.

(verified: app/Support/brand.php, app/Support/platform_config.php, PlatformConfigService.php, app/Features/)
