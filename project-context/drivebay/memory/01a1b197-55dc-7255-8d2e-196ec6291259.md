# DriveBay — architecture summary (final draft v4, replaces v1–v3)

Markers: *(verified: file)* = seen in the code; *(inferred)* = my conclusion; *(MAIW)* = from `D:\code\maiw\memory\drivebay`, not re-checked.

## Components

- **One Laravel 12 app with domain modules.**
  - 21 domains in `app/Domains/{Domain}/` hold services, jobs, console commands, DTOs, events and policies.
  - Models sit in a parallel tree, `app/Models/Domains/{Domain}/Models/`. There are 39 API controllers *(verified: ls)*.
- **Routing** *(verified: bootstrap/app.php, routes/)*:
  - `web.php`: the marketplace closure is mounted at `/` (English) and again at `/sr` with route names prefixed `sr.`.
  - `storefront.php`: dealer hosts.
  - `api.php` → 11 files in `api/v1/`.
- **Middleware** *(verified: bootstrap/app.php, AppServiceProvider)*:
  - `ResolveDealerStorefrontHost` runs first on every web request. It sets a request-wide `StorefrontContext` to marketplace or standalone, or returns 404 for an unknown host.
  - Then `SetLocale`, `EnsureEngagementVisitor` and `HandleInertiaRequests` run. The API adds `SetApiLocale`.
  - API rate limiters: `api-auth` 10/min per IP, `api-search` 60/min, `api-analytics` 120/min, `api-write` 30/min, `api-import-status` 180/min, plus one for the AI fuel estimate.
- **Admin:**
  - Filament 5 panel at `/admin` in SPA mode, open only to staff (`User::canAccessPanel` → `StaffAccessService`).
  - 32 resources and 3 widgets.
  - 10 custom pages: settings, taxonomy imports, fuel-price sync, a push tester, and the `super_admin`-only `ArtisanCommands` (a fixed command list run through `Artisan::call`) and `DeveloperTools`.
  - *(verified: AdminPanelProvider, User.php, Filament/Admin/Pages)*
- **Frontend:**
  - Inertia + Vue: 41 pages, four layouts, about 100 components, 24 composables.
  - Translations arrive as shared props passed through `brandify()`; there is no vue-i18n. Only 2 files use axios *(verified)*.
  - **Production is client-rendered**: the Dockerfile builds only `npm run build` and the web container has no Node process. Blade renders the SEO and OG meta on the server from `page.props.seo` *(verified: Dockerfile, resources/views/app.blade.php)*.
- **Helpers:**
  - `brand()` / `brandify()`, with packs in `config/brands/`.
  - `platform_config()`: boolean keys resolve through Pennant flags in global scope; other keys use a stored admin override, falling back to config *(verified)*.

## Data flow

1. **Creating a listing (web)** *(verified: SellerListingController, ListingMediaService, ProcessListingMediaJob, ListingPublishCoordinator)*:
   - `createDraft(CreateListingDTO)` → link to the dealer → sync equipment.
   - **With photos:** the status becomes `processing` and each photo is queued as a `ProcessListingMediaJob` (watermark + variants). When the last asset finishes, the listing is published with auto-approve.
   - **Without photos:** it is published immediately.
2. **Publishing** *(verified: ListingService)*:
   - Auto-approve → `active`/`approved`, then `ListingPublished` and `SyncListingSearchDocumentJob`.
   - Otherwise → `pending_review` and a notification to staff.
   - The manual publish action auto-approves only `private` users.
   - Statuses are plain strings: `draft`, `processing`, `pending_review`, `active`, `rejected`, `sold`, `archived`.
3. **Imports (Autodiler):** `ListingModerationPipelineService` + `ListingAutoPublishEvaluator` decide, guided by the photo-approval and auto-publish platform settings *(verified)*.
4. **Events:**
   - The only domain event is `ListingPublished`; its listeners are the seller notification and saved-search matches.
   - Observers: `NotificationObserver` (push, per MAIW) and `AdvertisementObserver`.
   - The rest is direct service calls and jobs *(verified: AppServiceProvider)*.
5. **Search:**
   - `ListingSearchDocument` rows are indexed in Meilisearch.
   - Filterable and sortable attributes are set in `config/scout.php` and apply only after `composer run search:setup`.
   - Sort scores: freshness, popularity, quality, recommendation and boost *(verified)*.
6. **Recommendations** *(verified: config/recommendations.php, routes/console.php)*:
   - The listing score is a weighted blend of capped signals: views 0.20, favorites 0.15, leads 0.15, phone 0.10, freshness 0.15, boost 0.15, quality 0.10.
   - Candidates come from content-based (20), collaborative (15) and trending (10) sources, weighted 0.75, 0.65 and 0.55.
   - Rebuilt nightly from 03:00 to 04:00. All tuning lives in config.
7. **Payments:** the gateway comes from `platform_config('billing.gateway')`. It returns Paddle or Stripe only when their keys are set; **otherwise it silently returns `FakePaymentGateway`** *(verified: AppServiceProvider:46-58)*.
8. **Errors:** web 403/404/500/503 render the Inertia `Error` page. The API returns JSON in a `{data, meta}` envelope *(verified)*.

## Boundaries and integrations

- **API:**
  - Sanctum bearer tokens, the `Accept-Language`, `X-Visitor-Id` and `X-Analytics-Source` headers.
  - Scramble exports `docs/api/v1/openapi.json` (122 operations).
  - 9 API controllers reuse `Requests\Web\*` despite the rule that web and API are separate contracts *(verified)*.
- **Datastores:** PostgreSQL 16, Redis 7, Meilisearch 1.12. 149 migrations; 129 tables in the DBML *(verified)*.
- **External services** *(verified: env names in config/)*:
  - Payments: Stripe and Paddle.
  - Firebase FCM.
  - Sentry and Telescope.
  - Socialite logins: Google, Facebook, Apple.
  - OpenAI, for fuel-consumption estimates.
  - Meta Graph, for Instagram (fake publishers for dev).
  - Vehicle data: mobile.de, plus CarQuery and NHTSA (legacy).
  - Autodiler and the Montenegro fuel-price feed.
- **Deployment** *(verified)*:
  - One Docker image with three targets: web (php-fpm + nginx), worker (Horizon) and scheduler.
  - Coolify runs the app, Horizon, Postgres, Redis and Meilisearch; the scheduler is a cron entry.
  - Horizon has two supervisors: `default`, and `autodiler-imports` on `redis-imports`.
- **Tickets:** the team tracks them in Jira `KAN` (epic `KAN-4`). NEXUS tasks reference KAN keys *(verified: D:\code\maiw\core\JIRA.md)*.

## Key decisions

- **A modular monolith by domain,** able to move to services later *(verified: docs/architecture/system-overview.md)*.
- **Brands are packs chosen at deploy time** (`BRAND`) *(MAIW; packs verified)*.
- **Locale lives in the URL** for the web and in a header for the API *(verified)*.
- **Long imports get their own queue, connection and supervisor** (KAN-7): timeouts ordered 900 s < 960 s < 1200 s *(verified)*.
- **Publish first, moderate after** for most listings *(code verified; policy inferred)*.
- **Production is client-rendered,** with the meta rendered on the server *(verified)*.
- **Image processing is custom.** Spatie Media Library was removed (KAN-16). **Paddle is a third gateway,** not Cashier. **Spatie roles are the source of truth for staff** *(MAIW; code verified)*.

## Risks and follow-ups (decided in the learning session; NEXUS backlog tasks)

- **Silent fake payments** when a gateway key is missing; no test covers the selection. → *Task: fail loudly when the configured payment gateway has no keys* (high).
- **Inconsistent publish rule:** a dealer's manual publish needs review, but creating a listing doesn't. The rule dates from the Alpha v1 commit `ffd813b`. Recommendation: one rule, auto-approve plus moderation afterwards, with the evaluator only for imports; needs product sign-off. → *Task: unify the listing publish rule.*
- **Documentation drift** → *Task: bring drivebay docs back in line with the code.*
  - **DBML:** about 13 missing tables, role tables that don't match Spatie, and the unused `media` table.
  - **API module docs:** about 12 undocumented endpoints, and one documented endpoint with no route (`PUT /seller/listings/{publicId}/viewing`).
  - **OpenAPI:** lacks `complete-profile` and `paddle/complete`.
  - **The repo's CLAUDE.md** is out of date.
- **Dev runs SSR but production doesn't.** Decision: keep production client-rendered and drop SSR from `composer run dev`. → *Task: make dev match production* (low).
- **MAIW wrapper rules** (auto memory sync, auto-push) duplicate NEXUS. Decision: keep the attribution rule, ask-before-app-push and Jira KAN; retire the sync and push for drivebay; keep `memory/drivebay` as a read-only archive. → *Task: retire the MAIW auto-sync rules for drivebay.*
- **Tests** use SQLite in memory with a sync queue, while production uses Postgres and Redis. Accepted for now; add Postgres-specific tests where queries depend on it *(inferred)*.
- **Pennant registration:** `AppServiceProvider` defines 13 of the 15 feature classes *(verified)*. Low risk.
