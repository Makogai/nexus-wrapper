`AppServiceProvider` binds `PaymentGatewayInterface` from `platform_config('billing.gateway', 'fake')`, so admins can override it. The underlying environment variable is `PAYMENT_GATEWAY`.

- `paddle` is used only if `config('drivebay.billing.paddle_api_key')` is filled. It also needs `PADDLE_CLIENT_TOKEN`, `PADDLE_WEBHOOK_SECRET` and the `PADDLE_PRICE_FEATURED_{HOME,SOCIAL}_{1,3,7}` catalog price IDs.
- `stripe` is used only if `config('drivebay.billing.stripe_secret')` is set.
- **In every other case it returns `FakePaymentGateway` without any error or log.** A production deployment with a missing key would therefore complete promotions without charging.

Related pieces:
- Webhooks: `POST /webhooks/stripe` and `/webhooks/paddle` (exempt from CSRF).
- Paddle also needs client-side completion: `/billing/paddle-checkout/complete` (web) and `POST /api/v1/billing/paddle/complete` (API). The API one is missing from `openapi.json`, which was last exported 2026-08-03.

When debugging "payment succeeded but nothing was charged", check the resolved gateway first.
