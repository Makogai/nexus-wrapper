- Tests use Pest 4 with about 144 `*Test.php` files in `tests/Feature` and `tests/Unit`, plus `tests/Support` and `tests/fixtures`. There is no `tests/Browser`, although CLAUDE.md documents one.
- Run them with `php artisan test --compact`, adding `--filter=` to narrow the run. `composer test` also clears the config cache first.
- `phpunit.xml` sets `DB_CONNECTION=sqlite`, `DB_DATABASE=:memory:` and `QUEUE_CONNECTION=sync`. So Postgres-specific SQL and queue timing or retry behaviour are not exercised by tests (inferred risk).
- CI (`.github/workflows/tests.yml`) runs on push to main or master and on every PR:
  - PHP 8.4: `composer install`, `cp .env.example .env`, `php artisan test --compact`;
  - then `npm ci && npm run build`.
- A second workflow, `php-base-image.yml`, builds the PHP base Docker image.
- Format PHP with `vendor/bin/pint --dirty` (AGENTS.md).

Agent-shell gotcha (MAIW NOW.md, 2026-08-05): node and npm may not be on PATH in the agent shell, so `npm run build` cannot be assumed to run.

(verified: phpunit.xml, .github/workflows/, tests/ listing)
