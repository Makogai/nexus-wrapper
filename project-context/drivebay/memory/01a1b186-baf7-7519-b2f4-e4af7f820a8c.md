Listing `status` values are plain strings, not an enum: `draft`, `processing`, `pending_review`, `active`, `rejected`, `sold`, `archived`. A separate `moderation_status` field holds `approved` or `pending`.

Paths into `ListingService::publish($listing, $autoApprove)`:

- **Web create with photos** (`SellerListingController`):
  - status → `processing`, then each photo is queued with `ListingMediaService::queueFromUpload` → `ProcessListingMediaJob` (watermark + variants).
  - When none of the listing's `MediaAsset`s is still `queued` or `processing`, `ListingPublishCoordinator::checkListingReady` publishes with `autoApprove: true`.
- **Web create without photos:** published at once, with `autoApprove: true`.
- **Manual "publish" action** (web `SellerListingController::publish`, API `SellerListingApiController`): `autoApprove` is true only when `user.type === 'private'`. Other user types (such as `dealer_employee`) go to `pending_review`, and staff are notified (`AdminStaffNotificationService`). Publishing is refused while the status is `processing`.
- **Autodiler imports:** `ListingModerationPipelineService::runForListing` → `ListingAutoPublishEvaluator`. The platform settings `moderation.require_admin_photo_approval` and `moderation.auto_publish_imports` decide whether photos and listings auto-approve.

The auto-approve branch fires the `ListingPublished` event (seller notification and saved-search matches) and queues `SyncListingSearchDocumentJob`. `update()` also re-syncs the search document.

Open question: is it intended that dealers' manual publish needs review while their create-with-photos path does not?

(verified: ListingService.php, SellerListingController.php, ListingMediaService.php, ListingPublishCoordinator.php, ListingModerationPipelineService.php)
