`D:\code\maiw` is the "makogai-ai-wrapper". It was used before NEXUS to give Claude, Cursor and Codex shared, low-token continuity.

Layout:
- `apps/<name>/`: the app repos, each its own git repo. Here: `drivebay`, and `drivebay-flutter`, which the user will add to NEXUS later as its own project.
- `memory/<name>/`: `NOW.md` (handoff), `INDEX.md` (router), `topics/*.md` and `meta.json` (with `sourceCommit`).
- `core/*.md`: the operating contract.
- `bin/`: `maiw.js`, `memory.js` (`status` and `validate`), `register.js`.
- `templates/`, plus adapters under `.claude/`, `.cursor/` and `.agents/`.

Its CLAUDE.md is still loaded in sessions under `D:\code\maiw`. Its rules:
- auto-commit and auto-push the wrapper after memory changes, but ask before committing or pushing `apps/*`;
- never credit an AI as git author or co-author;
- refresh the repos before substantive work;
- update `memory/<app>` after every app code change;
- keep Jira `KAN` as the ticket source of truth.

Gotcha: re-running `bin/register.js` overwrites the app's `AGENTS.md` and `CLAUDE.md` with a generic stub. drivebay's originals were kept by appending a MAIW section instead (MAIW decisions, 2026-07-15).

Open question for the user: which of these MAIW rules still apply now that NEXUS tracks the work?
